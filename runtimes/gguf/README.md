The comparison is justified by the runtime research question. Q4_K_M weights are 5,780,090,816 bytes. The phase was initially blocked because downloading them would leave about6.7 GiB free. The user then freed RAM/disk; the cleared-host baseline shows15.54 GiB free, enough to attempt this phase while preserving8 GiB. It is scheduled after the MLX/Bonsai runs, with no simultaneous loaded models. Installation alone is not an inference result.

Run `scripts/setup_gguf.sh` with lab servers stopped. It uses isolated CMake4.4.4 and an independent llama.cpp checkout pinned to `d327bf1f0780f87b8c01b367b61853b0c291d7c4`, builds only llama-server with Metal and two compilation jobs, then reuses the guarded HF downloader to fetch only Q4_K_M. It preserves unexpected existing checkout/model paths and never changes the Bonsai fork.

When sufficient disk exists, use a **separate pinned checkout** of https://github.com/ggml-org/llama.cpp at `runtimes/gguf/llama.cpp`, build Metal with CMake (`-DGGML_METAL=ON`, release, target llama-server), record the SHA and CMake version, then download **only** `Ornith-1.5-9B-Q4_K_M.gguf` from `ornith-ai/Ornith-1.5-9B-GGUF` revision `abdd624b12ebf020b767fff532ff44fe552b28c3` into the shared cache and link it as `models/ornith-gguf.gguf`. Check reserve immediately before and throughout download. No vision projector is required for these text tasks.

The launcher expects the independent binary at `runtimes/gguf/llama.cpp/build/bin/llama-server` and starts one slot on localhost:8083 using the same fixed context/output profile as MLX, full GPU offload, Jinja tool parsing, temp0.6/top_p0.95. Re-query `/v1/models`; perform API parser tests and 3/3 actual OpenCode cycles before any task scores. A successful build or candidate config does not establish those capabilities.

Run identical fresh F7 task copies and the same short requests as MLX. Runtime-specific quantization (MLX affine4 vs GGUF Q4_K_M) is an unavoidable confound: do not attribute a quality difference solely to runtime. Never load the two model variants concurrently.
