The first execution consumed ≈45k uncached input tokens; at the measured ≈83 t/s prefill that is ≈540 s, so the wall was probably spent reading context — an inference from those figures, not a per-step timing. Decision: rerun the official-core stage with `--editor-timeout 1800`, which sets the wall of every editor-side call (inventory/propose and selection both go through `LocalProposer`, built from the proposer channel; the selector channel entry is unused); the solver/DEV-execution wall (600 s) and the fixed profile stay unchanged. The rerun reuses the completed fresh source control `c20261108` (F7-A/B/C fail, D pass; same pinned executor, same cohort; Docker-state confound already recorded) so the treatment is compared with the same control; smoke, DEV base and editor are rerun in a new run directory. Attempt 1 logs are archived in `logs/archive-official-20261108-attempt1/`. Reporting: attempt 1 (600 s, no proposal) and the 1800 s rerun are separate rows; a rerun that still yields no validated changed harness is a pipeline result for Ornith MLX at this profile, not a model-quality score, and D033's gate (revisit the tuning plan before other models) applies. Candidate cohort `oc226-nodocker` is queued behind the rerun.
- D038: **Editor/solver decoupling principle, pre-registered 2026-11-08 before any `oc226-nodocker` candidate result** (fourth council, user decision "decide after measuring"). Evidence: upstream Harness² defaults the editor (`HARNESS2_IMPROVER_MODEL`) to the solver model but allows a separate one, and its editor channel defaults are 120 steps / 3600 s, versus this lab's 12 steps / 600 s (D037 rerun raises only the wall to 1800 s). In attempt 1, 5–6 editor executions hit the wall (9–11 tool calls, near the 12-step cap), the one that ended left the harness byte-identical to base, and DEV with the two byte-identical candidate harnesses still failed after 5 tool calls without a timeout (the solver may fail independently of guidance — not yet tested). Decision: (1) **"Ornith edits Ornith"** stays a separate labelled arm; if the D037 rerun yields no validated changed harness it is reported **N/E for tuning** (pipeline result, not a model-quality score) and does **not** gate the tuning of other models. (2) A **fixed-editor cross-model arm** (one editor model for every solver; label "cross-model editor", never "official Harness² self-optimization") is the intended way to tune other models. (3) The editor's identity is chosen **after the cohort but before any D033 tuning run**, using only measured editor feasibility — the model's own prefill t/s from its cohort micro/direct benchmarks versus the real editor input (≈45k uncached tokens; feasible only if read time ≤ the editor wall) — and **no F7 score of any tuning arm**; it is then recorded as a new decision before the first tuning run. Known constraint: Bonsai 2 27B prefill ≈22 t/s ⇒ ≈34 min to read 45k tokens, infeasible at an 1800 s wall unless the editor input is reduced. (4) Reducing the editor's input is an allowed, separately recorded change. (5) If no local editor is feasible, the outcome is reported as "Harness² not measurable locally at this profile (N/E)", not as zero. No change to the running campaigns.
